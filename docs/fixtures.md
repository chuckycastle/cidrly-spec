# Fixture format

Every file under `fixtures/` except `manifest.json` and `golden/` is a JSON object:

```jsonc
{
  "description": "what this fixture pins, in one sentence",
  "cases": [
    { "name": "optional", "input": { ... }, "expected": { ... } }
  ]
}
```

An implementation passes a fixture file when, for every case, running the engine on `input`
produces a value deep-equal to `expected` after applying the normalization rules in
`manifest.json`.

## Files

| File | Engine function under test |
| --- | --- |
| `engine/sizing.json` | expected devices + growth percentage -> planned devices, host bits, prefix, size, usable hosts |
| `engine/masks.json` | prefix -> netmask, wildcard, size for every prefix 0..32 |
| `engine/subnet-details.json` | network -> netmask, wildcard, first/last host, broadcast, gateway |
| `engine/containing-block.json` | set of networks -> smallest containing CIDR block |
| `engine/allocation.json` | plan -> allocated address per subnet id, supernet |
| `engine/ipam.json` | plan with assigned blocks -> allocation and free-space report |
| `engine/auto-fit.json` | subnets + blocks -> bin-packing result |
| `engine/overlap.json` | networks -> conflicts with complete/partial classification |
| `rules/vlan.json` | VLAN id -> reserved, confirmation required, per-vendor warning |
| `rules/ip-classification.json` | IP -> reserved range, private range |
| `format/plan-file.json` | plan JSON -> parsed values (defaults, migrations, preserved unknown fields) |
| `format/import-round-trip.json` | exported text -> parsed subnets, for every importable format |
| `golden/<plan>/<file>` | plan -> exact text export (timestamps replaced with `<timestamp>`) |

## Normalization

- ISO-8601 UTC timestamps in text outputs are replaced with the literal `<timestamp>` before
  comparison.
- `expected.subnets` arrays are sorted by `id`. All other arrays keep the order the engine produced,
  which is part of the contract (for example, fragment order in the free-space report).
- Percentages are rounded to six decimal places.
- Text is compared after normalizing line endings to `\n`.

## Generating

Fixtures are generated by the CLI, never edited by hand:

```bash
npm run fixtures -- /path/to/cidrly-spec/fixtures
```

The generator uses fixed ids and a fixed clock, so the output is byte-stable across runs.
